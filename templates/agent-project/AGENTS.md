# Project workflow

Use the task's GitHub issue as the acceptance and feedback record. Keep changes scoped to that issue and update `.agent-work/checkpoint.md` after meaningful milestones. Before resuming, inspect the saved checkpoint and current Git changes.

The user's instructions take precedence over skill guidance. Load only skills relevant to the task and installed framework version. Missing tools, permissions, or consequential ambiguity should be reported to the supervisor rather than worked around expensively.

Record the exact checks actually run and their results. A completed turn is not acceptance. Publication and merge follow the project's explicit authorization policy.
