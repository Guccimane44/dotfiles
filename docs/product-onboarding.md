# Product onboarding after v0.1.0

Vocabularium is not registered, inspected, or modified by the infrastructure release.
The next task should establish its actual stack, current repository state, and product
acceptance criteria before approving implementation work.

1. Record its GitHub repository, default branch, architecture, user journeys, and
   reproducible setup in a project contract using templates/agent-project. Preserve
   existing work; identify the source of truth for product decisions.
2. Make build/type checks, unit/integration tests, and appropriate browser or user-flow
   checks executable. Define observable acceptance criteria for one bounded issue.
   Structural contract validation alone does not establish readiness.
3. Explicitly authorize a manual pilot and its model budget. Classify simple drafting
   for Luna and complex implementation for Astra. Use the shared four-slot pool;
   the first pilot can be one representative issue without changing the capacity limit.
4. Run the issue in an isolated worktree. Exercise a planned stop and saved-session
   resume under supervisor control, verify actual results, and publish a reviewable PR
   only within the task authorization. Record total worker and supervisor cost where
   available; mark missing accounting unknown. Do not equate tokens with subscription cost.
5. Before automatic product dispatch, generalize the scheduler, console, and recorded
   verification/review paths from their current dotfiles-only repository boundary.
   Require an explicit allowlist, project checks, and isolation/recovery tests. Do not
   merely change the hardcoded repository or reuse dotfiles test commands as product proof.
6. Expand to independent product issues after the pilot passes. Review results rather
   than automatically retrying failures. Merge authority and product decisions stay
   with the authorized owner/supervisor relationship.

No new framework, skill pack, or external expertise is required by default. Retrieve
optional references only when they can resolve a specific remaining decision.
